# SpeakCV Chat Demo Presentation Script Design

## 1. Goal
Create an English presentation script for the SpeakCV chat/interview demo that is:
- natural and safe to speak
- easy to understand for a mixed audience
- flexible enough to fit a 5-10 minute demo and stretch naturally to 10-15 minutes
- aligned with the current planner-first interview direction in SpeakCV

The script should help the presenter sound smooth without needing advanced vocabulary.

---

## 2. Audience
The target audience is mixed:
- non-technical listeners who need a simple explanation
- semi-technical listeners who want to understand the product logic
- technical listeners who want to hear at least a few concrete system strengths

Because of this, the language should stay simple and accessible, while still highlighting that the product is more than a generic chatbot.

---

## 3. Core message
The presentation should communicate one balanced message:

> SpeakCV is not only a chat interface. It is an interview coach that uses CV and JD context, asks follow-up questions for a reason, and gives useful coaching after the session.

This message should stay visible throughout the script.

---

## 4. Presentation style
The recommended style is a narrated product demo.

### Why this style
- easiest for the presenter to follow live
- works well for mixed audiences
- easy to shorten or extend
- keeps attention on the visible product flow

### Tone rules
- use common English words
- keep sentences short
- avoid heavy technical terms unless briefly explained
- sound calm, clear, and practical rather than overly sales-driven

---

## 5. Script package deliverables
The final output should include three pieces.

### 5.1 Main script
A complete English script that follows the approved structure and can be used as the primary speaking version.

### 5.2 Shorter practice version
A shorter version of the same message that is easier to rehearse and memorize.

### 5.3 Bridge sentence set
A set of optional transition lines that let the presenter naturally extend the talk to around 10-15 minutes without sounding repetitive.

These bridges should be easy to insert between demo steps.

---

## 6. Approved structure
The script should follow this order.

### 6.1 Opening
Explain what SpeakCV is in one simple idea.

### 6.2 Problem
Explain briefly why many mock interview tools feel generic or not very useful.

### 6.3 Demo flow
Walk through the product in this sequence:
1. setup with CV, JD, or interview context
2. start the conversation
3. show the AI response and next question behavior
4. explain why the next question feels relevant
5. highlight the coaching or report value after the interview

### 6.4 Closing
Summarize the user value in plain language.

### 6.5 Flexible bridges
Add optional lines for extending the explanation smoothly.

---

## 7. Product alignment
The script should stay consistent with the current project direction visible in the codebase and design docs:
- the interview loop is centered in the chat/interview flow
- the system uses structured interview analysis
- the product direction emphasizes planner-first behavior
- the main visible value is explainable next-question selection plus coaching

The script should not claim features that are not grounded in the current direction.

---

## 8. Scope boundaries
### In scope
- spoken English demo script
- simple vocabulary
- mixed-audience framing
- flexible time control up to around 10-15 minutes
- product explanation tied to current chat/interview flow

### Out of scope
- deep technical architecture presentation
- investor-only pitch framing
- highly formal business script
- long 20-30 minute presentation structure

---

## 9. Success criteria
The script is successful if:
- the presenter can read it naturally without sounding robotic
- non-technical listeners understand the value quickly
- technical listeners can still hear a clear product logic
- the presenter can shorten or extend the talk without losing the main message
